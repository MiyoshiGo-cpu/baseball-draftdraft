## 0. この文書について

- **目的**：「ドラフト×ドラフト メーカー」（draft-draft.vercel.app）のゲーム性を、自分用に**一から再現**する（Phase 1）。そのうえで、選手の成績表示などの自分専用の改良を加える（Phase 2 以降）。
- **元祖のコードは使わない**。元祖のソースは公開されていないため、ルールだけを参考にして独自に実装する。
- 元祖の挙動で確認できなかった点は、本作の仕様として決めて §9 にまとめた。あとから変えられるよう、設定値で切り替えられる作りにしておく。
- 実装は Claude Code / Codex に任せる前提で、受け入れ条件（§8）をチェックリストにしている。

## 1. ゲーム概要

ルーレットで決まった「球団×年度」のドラフト指名選手から1人ずつ選び、17人の最強チームを作るゲーム。

1. 年度範囲とパス上限を設定する
2. ルーレットを回すと「球団×年度」が1つ決まる（同じ組み合わせは二度出ない）
3. その球団・年度の指名選手一覧から**1人だけ**選び、空いている枠に配置する（いらなければパス）
4. 一度配置した選手は、打順・守備位置も含めて**変更できない**
5. 17枠が埋まったら完成

面白さの中心は「今の1人を取るか、後の枠のために温存するか」の賭けにある。枠を早く埋めすぎると、守備位置がめちゃくちゃになる、欲しい打順や先発の枠が先に埋まる、といった「詰み」が起きる。

## 2. ルール

### 2.1 設定

| 項目 | 範囲 | 初期値 | 備考 |
|---|---|---|---|
| 年度範囲（開始〜終了） | 1965〜2025 | 1965〜2025 | 開始 ≤ 終了 |
| パス上限 | 0〜10 | 3 | |
| 育成指名を含める | ON/OFF | ON | 2005年以降が対象 |
| 入団拒否の選手を含める | ON/OFF | ON | |
| 効果音 | ON/OFF | ON | |

- 設定を変えられるのは**1回目のスピンの前だけ**。途中で変えたい場合はリセットする。
- 範囲内の有効な「球団×年度」の数が17未満の場合は、開始できないようにしてメッセージを出す。

### 2.2 ルーレット

- 抽選の対象は、次の条件をすべて満たす「球団スロット×年度」のペア。
  - 年度範囲内である
  - 指名データが存在する（例：1978年の巨人は不参加なので存在しない）
  - このゲームでまだ出ていない
  - 設定の絞り込み（育成・入団拒否）を適用した後でも、指名選手が1人以上いる
- 対象の中から一様ランダムに1ペアを選ぶ。
- 演出は「球団リール」と「年度リール」が回って止まる形（約1.5秒、効果音つき）。
- 今のスピンで選手を配置するかパスするまで、次のスピンは押せない。
- URL に `?seed=123` を付けると乱数を固定できるようにする（動作確認用）。

### 2.3 指名（選手を選ぶ）

- 名鑑の一覧から1人をタップして選び、「チームに追加」を押すと配置画面（§5.5）が開く。
- 今の空き枠に入れられない選手はグレーアウトし、理由を表示する（例：「同じ選手がチームにいます」）。
- **同一人物は2回チームに入れられない**。入団拒否のあと別の年度で再指名された選手などが対象で、`playerKey` で判定する（§4.3）。

### 2.4 配置（枠に入れる）

**枠構成（計17）**

| 区分 | 枠 | 数 |
|---|---|---|
| スタメン | 打順1〜9番 × 守備位置（捕・一・二・三・遊・左・中・右・DH） | 9 |
| 控え野手 | 控え | 2 |
| 投手陣 | 先発 | 3 |
| | 中継ぎ | 2 |
| | 抑え | 1 |

**配置ルール**

- **投手と野手の区別はしない（Beta v1.4〜）**。どの選手も、スタメン・控え・先発・中継ぎ・抑えのどの枠にも入れられる。糸井嘉男・雄平のように投手から野手へ、根尾昂のように野手から投手へ転向した選手もいるため、指名時の登録ポジションで枠を縛らない。
  - 登録ポジション（`投手` `捕手` `内野手` `外野手`）と二刀流フラグ（`twoWay`）は、肩書きとして表示するだけにする。データの `group`（P/F）も表示の色分けにだけ使う
  - Beta v1.3 までは「厳格」（投手は投手枠だけ、野手はスタメン・控えだけ）と「ゆるめ」を設定で選べたが、なくした
- 1人が入れるのは1枠だけ。
- **守備位置も登録ポジションと関係なく自由**。捕手登録の選手を遊撃に置いてもよい。悩みどころと「詰み」はここから生まれる。
- スタメンに入れるときは「守備位置」と「打順」を両方選ぶ。どちらも、まだ埋まっていないものだけ選べる。
- 確定の前に「確定すると変更できません」と確認を出す。確定後は移動も入れ替えもできない。

### 2.5 パス・自動スキップ

- パスはパス上限まで使える。パスするとそのスピンは選手を取らずに終わる。
- **自動スキップ（救済）**：一覧の中に配置できる選手が1人もいない場合（例：一覧の選手が全員すでにチームにいる）は、パスを消費せずに「自動スキップ」として次へ進める。
- パスが残り0でも、配置できる選手が1人でもいれば、誰か1人を取らないと次に進めない。

### 2.6 終了条件

- 17枠がすべて埋まったら「完成」。
- 抽選できるペアがなくなって17枠が埋まらなかった場合は「未完成で終了」。

## 4. データ

### 4.1 出典とライセンス

- 出典：日本語版 Wikipedia「`{年}年度新人選手選択会議 (日本プロ野球)`」（1965〜2025年）
  - 例：`2012年度新人選手選択会議 (日本プロ野球)`
- ライセンス：CC BY-SA 4.0
  - `data/drafts.json` は CC BY-SA 4.0 として扱い、README と画面フッターに出典を書く。
  - アプリのコードは別のライセンスでかまわない。
- ブラウザから Wikipedia を直接読みに行くことはしない。事前にスクリプトで JSON を作り、アプリはその JSON だけを読む。

### 4.2 データ作成スクリプト（`scripts/build_drafts.py`）

Python 3 + `requests` + `beautifulsoup4` で作る。

> **クラウド環境で実行するときの注意**：Claude Code のクラウド環境は、標準のネットワーク設定だと許可リスト外のサイトにアクセスできない。取得が 403 などではじかれた場合は、環境設定の Network access を Custom にして、標準の許可ドメインを残したまま `ja.wikipedia.org` を追加する。

1. MediaWiki API で記事の HTML を取得する。
   `https://ja.wikipedia.org/w/api.php?action=parse&page={記事名}&prop=text&format=json&formatversion=2`
   - User-Agent を明示する（例：`baseball-draftdraft/0.1 (personal project)`）
   - 1リクエストごとに1秒待つ
2. 取得した HTML は `scripts/cache/{年}.html` に保存し、2回目以降はキャッシュから読む。`scripts/cache/` は `.gitignore` に追加してコミットしない。
3. 球団ごとの指名表を取り出す。列はおおむね「順位／選手名／守備／所属（＋結果・備考）」だが、年代で列の構成が違うため、ヘッダーの文字列で列を特定する。
4. 見出しで「新人選手選択会議」と「育成選手選択会議」を区別し、`draftType` を付ける。
5. 球団名は `scripts/franchise_map.json`（当時の球団名 → スロット id の対応表）で変換する。対応表にない名前が出たら処理を止めて一覧を出す。**推測で割り当てない。**
6. 手で直す内容は `scripts/overrides.json` に書く（二刀流フラグ、同姓同名の区別、表の崩れの補正など）。
7. 出力するもの：
   - `data/drafts.json`
   - `scripts/report.md`（検証レポート：年度×球団ごとの人数表、0人のペア、対応表にない球団名、入団拒否・育成の件数、近鉄と楽天の重なりチェック）

### 4.3 JSON スキーマ（`data/drafts.json`）

```json
{
  "meta": {
    "source": "Wikipedia日本語版「新人選手選択会議 (日本プロ野球)」各年度記事",
    "license": "CC BY-SA 4.0",
    "generatedAt": "2026-11-24T00:00:00+09:00",
    "yearFrom": 1965,
    "yearTo": 2025
  },
  "franchises": [
    { "id": "fighters", "short": "日本ハム" }
  ],
  "drafts": [
    {
      "year": 2012,
      "franchiseId": "fighters",
      "teamName": "北海道日本ハムファイターズ",
      "picks": [
        {
          "id": "2012-fighters-01",
          "order": 1,
          "roundLabel": "1位",
          "name": "大谷翔平",
          "playerKey": "大谷翔平",
          "pos": "投手",
          "group": "P",
          "from": "花巻東高",
          "draftType": "regular",
          "signed": true,
          "twoWay": true,
          "note": ""
        }
      ]
    }
  ]
}
```

| フィールド | 内容 |
|---|---|
| `order` | 球団内の並び順（表示とソート用の連番） |
| `roundLabel` | 記事の表記そのまま（`1位` `2巡目` `自由獲得枠` `希望入団枠` `逆指名` `育成1位` など） |
| `playerKey` | 同一人物の判定用。氏名の空白を除いたもの。同姓同名の別人は `overrides.json` で区別する |
| `pos` | 記事の表記そのまま（`投手` `捕手` `内野手` `外野手`） |
| `group` | `P`（投手）か `F`（野手）。`pos` から自動で決める |
| `from` | 指名時の所属（学校・会社など） |
| `draftType` | `regular`（新人）か `ikusei`（育成） |
| `signed` | 入団しなかった指名なら `false`。結果・備考の列に「拒否」「交渉権放棄」「指名取消」「指名無効」のいずれかがあるかで判定する |
| `twoWay` | 二刀流フラグ。`overrides.json` で付ける |
| `note` | 備考の原文 |

Phase 2 で成績などを足すときは、`playerKey` をキーにした別ファイル（例：`data/players.json`）で結合する。`drafts.json` 自体は増やしすぎない。

### 4.4 特殊ケース

| ケース | 扱い |
|---|---|
| 1978年の巨人 | ドラフト不参加。ペアを作らない |
| 1966年（1次・2次の2回開催） | 同じ年度にまとめ、`roundLabel` に「1次」「2次」を付ける（記事の「第1次ドラフト」「第2次ドラフト」の区切りで判定） |
| 2005〜2007年（高校生と大学生・社会人の分離ドラフト） | 同じ年度にまとめ、`roundLabel` に「高校」「大社」を付ける |
| 逆指名・自由獲得枠・希望入団枠 | `roundLabel` に記事の表記をそのまま入れる |
| 育成指名 | `roundLabel` に「育成」を付ける（例：`育成1位`） |
| 「（選択権なし）」「（指名権剥奪）」の行 | 指名ではないので除く |
| 入団拒否から別年度で再指名された選手 | 別エントリとして両方残す。チームへの重複配置は `playerKey` で防ぐ |

### 4.5 選手データ（`data/players.json`、Beta v1.5〜）

- 出典：日本語版 Wikipedia の各選手の記事（CC BY-SA 4.0）。ドラフト記事の選手名リンクから記事を特定するので、同姓同名の別人を取り違えない。記事がない（赤リンク・リンクなし）選手はデータなし
- 作り方：`scripts/build_players.py`
  1. 記事の元の文章（wikitext）を 50 件ずつまとめて取得する（`action=query`）。1件ずつ取得すると、アクセス制限で何時間もかかるため
  2. 「年度別打撃成績」「年度別投手成績」「年度別守備成績」の節だけを、20 人ずつまとめて Wikipedia 側で HTML の表に変換して読み取る（`action=parse`）。表の見出しがテンプレートで書かれていて種類があるため
  3. 取得した記事と変換した表は `scripts/cache/players/` にキャッシュする（コミットしない）
  4. 検証レポート `scripts/players_report.md`（件数、抜き取り確認、NPB として扱わなかった球団表記）を出す
- 中身（`playerKey` ごと）：
  - `title`：記事名
  - `profile`：守備位置（記事の表記。例「投手→外野手」）、利き腕・打席、生年月日、出身地、身長・体重、経歴、プロ入り年度、初出場・最終出場
  - `batting` / `pitching`：NPB の一軍の年度別成績。列は `meta.battingColumns` / `meta.pitchingColumns` の順の配列で、最後にリーグ1位（記事で太字）の列番号の配列が付くことがある。MLB など NPB 以外の球団の年は入れない。シーズン途中の移籍は球団ごとに別の行
    - 表の見出しが縦書き（「セ丨ブ」「ホ丨ルド」のように長音を「丨」で書く）でも読み取る（Beta v1.6 で修正。それまではセーブ・ホールドが空だった）
    - 球団欄が「阪急 オリックス」のように複数年をまとめて書かれているときは、アプリ側（`js/stats.js` の `teamForYear`）でその年の球団名に直す
  - `fielding`：一軍の守備位置別の通算試合数（例 `{"外野": 1511}`）。指名打者は含まない。`fieldingYears` の合計
  - `fieldingYears`（Beta v1.8〜）：年度・球団・守備位置ごとの守備成績。列は `meta.fieldingColumns`（year, team, pos, G, PO=刺殺, A=補殺, E=失策, DP=併殺, SBA=盗塁企図数, CS=盗塁刺, PB=捕逸。最後の3つは捕手のみ）
    - 見出しが「遊撃(SS)」「一塁手」のような書き方でも読む。「左翼・中堅・右翼」と「外野（合計）」の両方がある年は、合計の行を使わない（Beta v1.8 で修正。それまでは「(SS)」付きの表を読めていなかった）
  - 打撃の列に、盗塁死（CS）と併殺打（GDP）を追加（Beta v1.8〜）
  - `titles` / `awards`：記事の「タイトル」「表彰」の一覧（原文をそろえたもの）
- KBO・CPBL の同名球団の行は除く（「ロッテ(G)」「楽天M」「青宝」、1977年以降の「太平洋」など。Beta v1.7 で修正）
- アプリは、選手の詳細を開いたときに初めて読み込む（大きいため）

### 4.6 リーグのデータ（`data/leagues.json`、Beta v1.7〜）

- 出典：NPB.jp 日本野球機構「年度別成績」（`https://npb.jp/bis/yearly/{central,pacific}league_{年}.html`）と、2005年以降の「チーム打撃成績」「チーム投手成績」（`https://npb.jp/bis/{年}/stats/tm{b,p}_{c,p}.html`）
- 作り方：`scripts/build_leagues.py`（1.5秒間隔で取得し、`scripts/cache/npb/` にキャッシュ）
- 中身：`leagues[年][C|P]` に、球団数・試合数・勝敗の合計、打撃（打数・得点・安打・二塁打・三塁打・本塁打・盗塁・四球・死球・犠飛、2005年以降は打席・犠打・盗塁刺も）、投手（アウト数・自責点・失点・奪三振、2005年以降は四球・死球・被本塁打・被安打も）
- 2005年より前の四球・死球・犠飛は公式の表にないので、選手データのその年・そのリーグの打数あたりの値から推定する（選手データの打数が少ない年は、その後10年の平均に寄せる）。`estimated: true` を付ける。2005年以降で試すと、推定と公式の差はおおむね ±5% 以内
- 用途：簡易 WAR の基準（§5.11）

## 5. 画面仕様

スマホを優先した縦1列のレイアウト（幅375pxを基準にし、タップ領域は44px以上）。画面が広いときは2列にする（左：ルーレット＋名鑑、右：マイチーム＋履歴）。

**見た目の方針（Beta v1.2〜）**：野球の育成ゲームのような見た目ではなく、ドラフト会議の中継画面をイメージする。白を基調に、紺（`#0b2a66`）と赤（`#e3002b`）を差し色にしたソーシャルゲーム風のデザインにする（立体感のあるボタン、紺色の上部バー、左に帯のある見出し）。ダークモードは使わず、いつも白い画面で表示する。

### 5.0 画面の構成（Beta v1.1〜）

野球ゲームのアプリのように、タイトル画面から始まる構成にする。

```
タイトル（遊ぶ）
└─ メニュー
   ├─ 新しく始める → ルール設定 →（ドラフト開始！）→ ゲーム → 選択終了（完成画面）
   ├─ 続きから → ゲーム
   ├─ 保存したチーム → チームの詳細
   ├─ 遊び方
```

### 5.1.1 バージョンと更新ログ
- 正式版を出すまではベータ版とし、「Beta v1.0」「Beta v1.1」…と表記する（これまでの版もすべて Beta 表記にした）。改良のたびに小数点以下を1つ上げる
- すべての改良が終わったら正式版 **v1.0** をリリースする。正式版のあとは、機能の追加・改善・修正やデータの更新で小数点以下を上げ（v1.1…）、大きな作り直しで整数部を上げる（v2.0）。正式版 v1.0 は、ベータ版のどの版よりも新しいものとして扱う
- 更新ログは `js/version.js` に新しい順で書く（段階・版・日付・見出し・変更内容。変更の種類は「追加」「改善」「変更」「修正」「データ」）
- リポジトリの `CHANGELOG.md` は `npm run changelog` で `js/version.js` から生成する。両者が食い違うとテストが失敗する

### 5.11 答え合わせ：キャリアハイと総合力（Beta v1.6〜。Beta v1.7 で簡易 WAR に変更）
- 表示する場所：完成画面（「選択終了」のカードの下。未完成で終わったときも埋まった枠だけで出す）、保存したチームの詳細
- 簡易 WAR（`js/war.js`）：控えレベルの選手と比べて何勝ぶん上積みしたか。年度・リーグの平均（§4.6）と比べる
  - 打者（年度・球団の行ごとに計算して足す）：
    - 打撃＝（wOBA − リーグの wOBA）÷ 割る数 × 打席（打数＋四球＋死球＋犠飛）。wOBA の重みは 四球 0.69、死球 0.72、単打 0.89、二塁打 1.27、三塁打 1.62、本塁打 2.10。割る数＝1.2 ×（0.122 ÷ リーグの1打席あたりの得点）^0.6（Beta v1.8〜。点が入りにくい年ほど大きい）
    - 走塁（Beta v1.8〜）＝盗塁 × 0.2 ＋ 盗塁死 × 盗塁死の価値 − リーグの平均 ×（単打＋四球＋死球）。盗塁死の価値＝−（2 × リーグの1アウトあたりの得点 ＋ 0.075）。盗塁死の記録がない行は、リーグ平均の割合（盗塁死÷盗塁）で失敗したとみなす
    - 守備（Beta v1.8〜）＝その年・その守備位置ごと（`fieldingYears`）に計算して足す。比べる相手は、同じ年の前後2年の、同じ守備位置の全選手（外野は左翼・中堅・右翼もまとめる）
      - 守備範囲（年間の試合数の 40% 以上守った年だけ。80% まで少しずつ増やす）：内野（二塁・三塁・遊撃）は補殺 × 0.75 点と併殺 × 0.2 点、一塁は補殺 × 0.4 点、外野は刺殺 × 0.8 点と補殺 × 0.4 点を、レギュラーの1試合あたりの平均と比べる。投手陣や球場の影響も受けるので 35% だけ数える
      - 失策＝（失策 − 守備機会 × 平均の失策率）× −0.4 点
      - 捕手＝（盗塁刺 − 盗塁企図 × 平均の阻止率）× 0.65 点 × 75% ＋（捕逸 − 平均）× −0.28 点
      - 1年・1つの位置で ±15点まで。投手の守備は数えない。守備成績がない選手は 0
    - 守備位置＝162試合あたり 捕手 +12.5、遊撃 +7.5、二塁・三塁・中堅 +2.5、外野（まとめて）−4、左翼・右翼 −7.5、一塁 −12.5 を、その年に守った試合数に掛ける（1試合で複数の位置を守った分は割り引く）。守備についていない試合は、指名打者のあるリーグ（パ・リーグ 1975年〜）なら指名打者 −17.5。その年の守備成績がなければ、通算の守備位置の試合数で混ぜる（それもなければプロフィールの守備位置、投手だけなら 0）
    - 控えレベルとの差＝打席 ×（打者に配る WAR × 1勝に必要な得点 ÷ リーグの打席）
  - 投手：
    - 平均との差＝（リーグの防御率 × 投球回 ÷ 9 − 自責点）×（リーグの失点 ÷ 自責点）
    - 控えレベルとの差＝アウト数 ×（投手に配る WAR × 1勝に必要な得点 ÷ リーグのアウト数）×（先発の割合 × 1.15 ＋ 救援の割合 × 0.6）
    - 救援の重み＝1 ＋ 救援の割合 × 0.5 ×（セーブ＋ホールド）÷ 救援登板（記録がない時代は 0.3 とみなす）
  - 1勝に必要な得点＝9 × 1回あたりの失点 × 1.5 ＋ 3（FanGraphs の式）。リーグ全体の WAR＝勝ち数 − 勝率 .294 × 勝敗数。打者 57%・投手 43%
  - 球場の違い・盗塁以外の走塁・捕手のリードは入れない
- 年度の自動選択（`js/career.js`）：その枠での WAR が最も高い年（打者の枠は打撃、投手の枠は投手）。中継ぎ・抑えの枠は、80回を超える年の WAR を 80回分に割り引く。WAR が出せない年しかないときは、Beta v1.6 の選び方（OPS・勝利数・セーブなど）で選ぶ。シーズン途中で移籍した年は1年にまとめる
- 選び直し：選手をタップすると、年度の一覧（新しい順、成績・ランク・WAR つき、自動で選ぶ年に「キャリアハイ」の印）が開き、別の年を選べる。自動の年を選ぶと「自動」に戻る。選んだ年度はゲーム状態の `careerYears` に入れ、保存したチームにも反映する
- 選手のランク：WAR 7以上 S、5以上 A、3以上 B、2以上 C、1以上 D、それ未満 E。中継ぎ・抑えの枠は 3.5・2.5・1.5・1・0.5
- チーム：WAR の合計（控えは 1/4）＋ 42勝（143試合 × .294）＝予想勝利数（0〜143）。ランクは 104勝以上 S（歴代最強クラス）、94 A（独走で優勝）、85 B（優勝争い）、77 C（Aクラス争い）、69 D（Bクラス）、それ未満 E（最下位争い）（Beta v1.8 で調整）。打線（スタメン・控え）と投手陣の WAR も出す
- 合計成績：スタメン9人の打率（安打÷打数）・本塁打・打点・盗塁、投手陣6人の勝利・セーブ・ホールド・防御率
- その枠の成績がない選手（投手の枠に一軍の投手成績がない選手など）は「一軍の○○成績なし」で0
- 共有：シェア画像に総合力（ランク・予想勝利数・チーム WAR・打線と投手陣の WAR・合計成績）と、各選手のキャリアハイの年度・成績・ランク・WAR を載せる。テキストのコピーは最後に「総合力 A（予想 91勝52敗・チーム WAR 48.6）打線 30.1・投手陣 18.5」の行を足す。選手データを読み込む前は今までどおり
- 保存したチームの一覧に、総合力のランクと予想勝利数を出す（保存したチームの `rating` に入れる）
- 選手の詳細（§5.10）の年度別の表と通算にも WAR を出す。打者は通算の内訳（打撃・走塁・守備・守備位置・控えとの差）も出す
- 答え合わせと年度選びでは、打者の WAR のうち守備と走塁の分を「うち守備 +1.2・走塁 +0.3」のように出す
