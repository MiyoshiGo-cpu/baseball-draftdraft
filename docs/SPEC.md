## 0. この文書について

- **目的**：「ドラフト×ドラフト メーカー」（draft-draft.vercel.app）のゲーム性を、自分用に**一から再現**する（Phase 1）。そのうえで、選手の成績表示などの自分専用の改良を加える（Phase 2 以降）。
- **元祖のコードは使わない**。元祖のソースは公開されていないため、ルールだけを参考にして独自に実装する。
- 元祖の挙動で確認できなかった点は、本作の仕様として決めて §9 にまとめた。あとから変えられるよう、設定値で切り替えられる作りにしておく。
- 実装は Claude Code / Codex に任せる前提で、受け入れ条件（§8）をチェックリストにしている。

## 1. ゲーム概要

ルーレットで決まった「球団×年度」のドラフト指名選手から1人ずつ選び、17人の最強チームを作るゲーム。

1. 年度範囲とパス上限を設定する
2. ルーレットを回すと「球団×年度」が1つ決まる（同じ組み合わせは二度出ない）
3. その球団・年度の指名選手一覧から**1人だけ**選び、空いている枠に配置する（いらなければパス）
4. 一度配置した選手は、打順・守備位置も含めて**変更できない**
5. 17枠が埋まったら完成

面白さの中心は「今の1人を取るか、後の枠のために温存するか」の賭けにある。枠を早く埋めすぎると、守備位置がめちゃくちゃになる、投手枠が埋まって大物投手を取れない、といった「詰み」が起きる。

## 2. ルール

### 2.1 設定

| 項目 | 範囲 | 初期値 | 備考 |
|---|---|---|---|
| 年度範囲（開始〜終了） | 1965〜2025 | 1965〜2025 | 開始 ≤ 終了 |
| パス上限 | 0〜10 | 3 | |
| 育成指名を含める | ON/OFF | ON | 2005年以降が対象 |
| 入団拒否の選手を含める | ON/OFF | ON | |
| 投手⇔野手の制限 | 厳格／ゆるめ | 厳格 | §2.4 参照 |
| 効果音 | ON/OFF | ON | |

- 設定を変えられるのは**1回目のスピンの前だけ**。途中で変えたい場合はリセットする。
- 範囲内の有効な「球団×年度」の数が17未満の場合は、開始できないようにしてメッセージを出す。

### 2.2 ルーレット

- 抽選の対象は、次の条件をすべて満たす「球団スロット×年度」のペア。
  - 年度範囲内である
  - 指名データが存在する（例：1978年の巨人は不参加なので存在しない）
  - このゲームでまだ出ていない
  - 設定の絞り込み（育成・入団拒否）を適用した後でも、指名選手が1人以上いる
- 対象の中から一様ランダムに1ペアを選ぶ。
- 演出は「球団リール」と「年度リール」が回って止まる形（約1.5秒、効果音つき）。
- 今のスピンで選手を配置するかパスするまで、次のスピンは押せない。
- URL に `?seed=123` を付けると乱数を固定できるようにする（動作確認用）。

### 2.3 指名（選手を選ぶ）

- 名鑑の一覧から1人をタップして選び、「チームに追加」を押すと配置画面（§5.5）が開く。
- 今の空き枠に入れられない選手はグレーアウトし、理由を表示する（例：「投手枠が満杯」「同じ選手がチームにいます」）。
- **同一人物は2回チームに入れられない**。入団拒否のあと別の年度で再指名された選手などが対象で、`playerKey` で判定する（§4.3）。

### 2.4 配置（枠に入れる）

**枠構成（計17）**

| 区分 | 枠 | 数 |
|---|---|---|
| スタメン | 打順1〜9番 × 守備位置（捕・一・二・三・遊・左・中・右・DH） | 9 |
| 控え野手 | 控え | 2 |
| 投手陣 | 先発 | 3 |
| | 中継ぎ | 2 |
| | 抑え | 1 |

**配置ルール**

- 選手の区分は、指名時の登録ポジションで決める。
  - `投手` → 投手（P）
  - `捕手` / `内野手` / `外野手` → 野手（F）
- 「厳格」設定（初期値）の場合：
  - 投手は投手枠（先発・中継ぎ・抑え）にだけ入れられる
  - 野手はスタメンか控えにだけ入れられる
- 「ゆるめ」設定の場合：投手もスタメン・控えに入れられる。ただし野手を投手枠に入れることはできない。
- 二刀流フラグ（`twoWay: true`）の選手は、設定にかかわらず投手枠・野手枠のどちらにも入れられる。ただし入れるのは1枠だけ。
- **野手の守備位置は登録ポジションと関係なく自由**。捕手登録の選手を遊撃に置いてもよい。悩みどころと「詰み」はここから生まれる。
- スタメンに入れるときは「守備位置」と「打順」を両方選ぶ。どちらも、まだ埋まっていないものだけ選べる。
- 確定の前に「確定すると変更できません」と確認を出す。確定後は移動も入れ替えもできない。

### 2.5 パス・自動スキップ

- パスはパス上限まで使える。パスするとそのスピンは選手を取らずに終わる。
- **自動スキップ（救済）**：一覧の中に配置できる選手が1人もいない場合（例：投手しかいないのに投手枠が満杯）は、パスを消費せずに「自動スキップ」として次へ進める。
- パスが残り0でも、配置できる選手が1人でもいれば、誰か1人を取らないと次に進めない。

### 2.6 終了条件

- 17枠がすべて埋まったら「完成」。
- 抽選できるペアがなくなって17枠が埋まらなかった場合は「未完成で終了」。

## 4. データ

### 4.1 出典とライセンス

- 出典：日本語版 Wikipedia「`{年}年度新人選手選択会議 (日本プロ野球)`」（1965〜2025年）
  - 例：`2012年度新人選手選択会議 (日本プロ野球)`
- ライセンス：CC BY-SA 4.0
  - `data/drafts.json` は CC BY-SA 4.0 として扱い、README と画面フッターに出典を書く。
  - アプリのコードは別のライセンスでかまわない。
- ブラウザから Wikipedia を直接読みに行くことはしない。事前にスクリプトで JSON を作り、アプリはその JSON だけを読む。

### 4.2 データ作成スクリプト（`scripts/build_drafts.py`）

Python 3 + `requests` + `beautifulsoup4` で作る。

> **クラウド環境で実行するときの注意**：Claude Code のクラウド環境は、標準のネットワーク設定だと許可リスト外のサイトにアクセスできない。取得が 403 などではじかれた場合は、環境設定の Network access を Custom にして、標準の許可ドメインを残したまま `ja.wikipedia.org` を追加する。

1. MediaWiki API で記事の HTML を取得する。
   `https://ja.wikipedia.org/w/api.php?action=parse&page={記事名}&prop=text&format=json&formatversion=2`
   - User-Agent を明示する（例：`baseball-draftdraft/0.1 (personal project)`）
   - 1リクエストごとに1秒待つ
2. 取得した HTML は `scripts/cache/{年}.html` に保存し、2回目以降はキャッシュから読む。`scripts/cache/` は `.gitignore` に追加してコミットしない。
3. 球団ごとの指名表を取り出す。列はおおむね「順位／選手名／守備／所属（＋結果・備考）」だが、年代で列の構成が違うため、ヘッダーの文字列で列を特定する。
4. 見出しで「新人選手選択会議」と「育成選手選択会議」を区別し、`draftType` を付ける。
5. 球団名は `scripts/franchise_map.json`（当時の球団名 → スロット id の対応表）で変換する。対応表にない名前が出たら処理を止めて一覧を出す。**推測で割り当てない。**
6. 手で直す内容は `scripts/overrides.json` に書く（二刀流フラグ、同姓同名の区別、表の崩れの補正など）。
7. 出力するもの：
   - `data/drafts.json`
   - `scripts/report.md`（検証レポート：年度×球団ごとの人数表、0人のペア、対応表にない球団名、入団拒否・育成の件数、近鉄と楽天の重なりチェック）

### 4.3 JSON スキーマ（`data/drafts.json`）

```json
{
  "meta": {
    "source": "Wikipedia日本語版「新人選手選択会議 (日本プロ野球)」各年度記事",
    "license": "CC BY-SA 4.0",
    "generatedAt": "2026-11-24T00:00:00+09:00",
    "yearFrom": 1965,
    "yearTo": 2025
  },
  "franchises": [
    { "id": "fighters", "short": "日本ハム" }
  ],
  "drafts": [
    {
      "year": 2012,
      "franchiseId": "fighters",
      "teamName": "北海道日本ハムファイターズ",
      "picks": [
        {
          "id": "2012-fighters-01",
          "order": 1,
          "roundLabel": "1位",
          "name": "大谷翔平",
          "playerKey": "大谷翔平",
          "pos": "投手",
          "group": "P",
          "from": "花巻東高",
          "draftType": "regular",
          "signed": true,
          "twoWay": true,
          "note": ""
        }
      ]
    }
  ]
}
```

| フィールド | 内容 |
|---|---|
| `order` | 球団内の並び順（表示とソート用の連番） |
| `roundLabel` | 記事の表記そのまま（`1位` `2巡目` `自由獲得枠` `希望入団枠` `逆指名` `育成1位` など） |
| `playerKey` | 同一人物の判定用。氏名の空白を除いたもの。同姓同名の別人は `overrides.json` で区別する |
| `pos` | 記事の表記そのまま（`投手` `捕手` `内野手` `外野手`） |
| `group` | `P`（投手）か `F`（野手）。`pos` から自動で決める |
| `from` | 指名時の所属（学校・会社など） |
| `draftType` | `regular`（新人）か `ikusei`（育成） |
| `signed` | 入団しなかった指名なら `false`。結果・備考の列に「拒否」「交渉権放棄」「指名取消」「指名無効」のいずれかがあるかで判定する |
| `twoWay` | 二刀流フラグ。`overrides.json` で付ける |
| `note` | 備考の原文 |

Phase 2 で成績などを足すときは、`playerKey` をキーにした別ファイル（例：`data/players.json`）で結合する。`drafts.json` 自体は増やしすぎない。

### 4.4 特殊ケース

| ケース | 扱い |
|---|---|
| 1978年の巨人 | ドラフト不参加。ペアを作らない |
| 1966年（1次・2次の2回開催） | 同じ年度にまとめ、`roundLabel` に「1次」「2次」を付ける（記事の「第1次ドラフト」「第2次ドラフト」の区切りで判定） |
| 2005〜2007年（高校生と大学生・社会人の分離ドラフト） | 同じ年度にまとめ、`roundLabel` に「高校」「大社」を付ける |
| 逆指名・自由獲得枠・希望入団枠 | `roundLabel` に記事の表記をそのまま入れる |
| 育成指名 | `roundLabel` に「育成」を付ける（例：`育成1位`） |
| 「（選択権なし）」「（指名権剥奪）」の行 | 指名ではないので除く |
| 入団拒否から別年度で再指名された選手 | 別エントリとして両方残す。チームへの重複配置は `playerKey` で防ぐ |

## 5. 画面仕様

スマホを優先した縦1列のレイアウト（幅375pxを基準にし、タップ領域は44px以上）。画面が広いときは2列にする（左：ルーレット＋名鑑、右：マイチーム＋履歴）。

**見た目の方針（Beta v1.2〜）**：野球の育成ゲームのような見た目ではなく、ドラフト会議の中継画面をイメージする。白を基調に、紺（`#0b2a66`）と赤（`#e3002b`）を差し色にしたソーシャルゲーム風のデザインにする（立体感のあるボタン、紺色の上部バー、左に帯のある見出し）。ダークモードは使わず、いつも白い画面で表示する。

### 5.0 画面の構成（Beta v1.1〜）

野球ゲームのアプリのように、タイトル画面から始まる構成にする。

```
タイトル（遊ぶ）
└─ メニュー
   ├─ 新しく始める → ルール設定 →（ドラフト開始！）→ ゲーム → 選択終了（完成画面）
   ├─ 続きから → ゲーム
   ├─ 保存したチーム → チームの詳細
   ├─ 遊び方
   ├─ オプション（効果音、データの削除・初期化、アプリの情報）
   ├─ 更新ログ
   └─ クレジット
```

| 画面 | URL | 内容 |
|---|---|---|
| タイトル | `#/title` | ドラフト会議の会場をイメージした白い画面。ロゴ、「会場モニター」（歴代の1位指名選手を「第1巡選択希望選手」として数秒ごとに発表）、「遊ぶ」ボタン、紺のフッター帯にバージョン表示（タップで更新ログ）と出典の短い表記。進行中のゲームがあれば一言添える |
| メニュー | `#/menu` | 「新しく始める」（大きなカード）、「続きから」（進行中・前回のゲームがあるときだけ。進み具合つき）、保存したチーム・遊び方・オプション・更新ログのタイル、クレジットへのリンク |
| ルール設定 | `#/setup` | §2.1 の項目（効果音を除く）。前回の設定を初期表示し、「初期設定に戻す」「ドラフト開始！」。進行中のゲームがあれば、消えることを確認する |
| ゲーム | `#/game` | §5.3〜§5.8。今回のルールを上部に小さく表示する。設定はここでは変えない |
| 保存したチーム | `#/saved`、`#/saved/<id>` | 一覧と詳細（テキストコピー・画像保存・削除） |
| 遊び方 | `#/howto` | 流れ、枠の構成、大事なルール、コツ |
| オプション | `#/options` | 効果音、進行中のゲームの破棄、保存したチームの全削除、全データの初期化、バージョンと収録データの情報 |
| 更新ログ | `#/changelog` | §5.1.1 |
| クレジット | `#/credits` | §11 の内容 |

- タイトル画面以外は、上部に「戻る」ボタン・画面名・効果音 ON/OFF のバーを置く。
- 画面左上の戻るボタンと、ブラウザやスマホの「戻る」のどちらでも前の画面に戻れる。ルール設定からゲームに進んだときは、戻るとメニューに戻る（ルール設定には戻らない）。
- URL を直接開いたりリロードしたりしても、その画面を表示する（ゲームがない状態で `#/game` を開いたらルール設定へ）。

### 5.1 画面上部のバー
- 戻る、画面名、効果音 ON/OFF（効果音はオプション画面でも切り替えられる）
- アプリのバージョン（例：`Beta v1.2`）はタイトル画面とメニューに表示する。タップすると更新ログを開く
- 前回見たときより新しいバージョンになっていたら、タイトル画面とメニューの「更新ログ」に「NEW」を付ける（更新ログを開くと消える）

### 5.1.1 バージョンと更新ログ
- 正式版を出すまではベータ版とし、「Beta v1.0」「Beta v1.1」…と表記する（これまでの版もすべて Beta 表記にした）。改良のたびに小数点以下を1つ上げる
- すべての改良が終わったら正式版 **v1.0** をリリースする。正式版のあとは、機能の追加・改善・修正やデータの更新で小数点以下を上げ（v1.1…）、大きな作り直しで整数部を上げる（v2.0）。正式版 v1.0 は、ベータ版のどの版よりも新しいものとして扱う
- 更新ログは `js/version.js` に新しい順で書く（段階・版・日付・見出し・変更内容。変更の種類は「追加」「改善」「変更」「修正」「データ」）
- リポジトリの `CHANGELOG.md` は `npm run changelog` で `js/version.js` から生成する。両者が食い違うとテストが失敗する

### 5.2 ルール設定（v1.0 までは設定パネル）
- §2.1 の項目を、ゲームを始める前のルール設定画面で決める（§5.0）。ゲームが始まったら変えられない

### 5.3 ルーレット
- 球団リール・年度リール
- 「ルーレットを回す」ボタン
- スピン回数、パスの残り回数

### 5.4 ドラフト名鑑
- 見出し：`2012年 北海道日本ハムファイターズ（指名7人）`
- 各行：順位ラベル／選手名／守備／所属／バッジ（育成・入団拒否・二刀流）
- タップで1人を選ぶ（1人だけ選べる）
- 選べない選手はグレーアウトし、理由を出す
- 下部に固定ボタン：「チームに追加」「パス（残り2）」

### 5.5 配置モーダル
- 選手名と区分（投手／野手）
- 投手の場合：「先発」「中継ぎ」「抑え」（空き数つき、満杯は押せない）
- 野手の場合：
  - 「スタメン」か「控え」を選ぶ
  - スタメンなら、守備位置ボタン9個と打順ボタン9個（埋まっているものは押せない）
- 「確定（変更不可）」と「戻る」

### 5.6 マイチーム
- 進捗：`12 / 17`
- スタメン（打順順）：打順・守備・選手名・`'12 日本ハム 1位`
- 控え（2）、投手陣（先発3・中継ぎ2・抑え1）
- 空き枠は点線で表示する

### 5.7 スピン履歴
- 新しい順に表示：回数／年度／球団（当時名）／結果（`大谷翔平 → 4番・右翼`、`パス`、`自動スキップ`）

### 5.7.1 指名の発表（Beta v1.2〜）
- 選手を枠に確定すると、ドラフト会議の読み上げのような発表カードを出す：「第○巡選択希望選手」（○はチームに入れた順番。1〜17）、指名当時の年度・球団・順位、選手名、守備・所属、入れた枠、「交渉権確定」のはんこ
- 会場のチャイムのような効果音を鳴らす。タップするか約3秒で閉じる
- 17人目のあとは「選択終了」の発表を続けて出す
- マイチームと抽選履歴にも、何巡目に指名した選手かを表示する

- 「選択終了」のバナー、指名人数、スピン回数、パス使用回数

## 6. 状態モデルと保存

### 6.1 ゲーム状態

```js
{
  settings: { yearFrom, yearTo, passLimit, includeIkusei, includeUnsigned, pitcherFielderRule, sound },
  seed: 123,                      // 乱数シード

  roster: {

    bench: [],
    SP: [], RP: [], CL: []
  },

  ]
```

### 6.2 保存（localStorage）

| キー | 内容 |
|---|---|
| `dr.settings` | 前回の設定 |
| `dr.current` | 進行中のゲーム。操作のたびに保存し、リロードしても途中から再開できるようにする |
| `dr.saved` | 完成したチームの一覧（最大50件） |

- localStorage の読み書きはすべて try/catch で囲む（使えない環境でも落ちないようにする）。
- ログインやクラウド保存は作らない（自分専用のため）。
