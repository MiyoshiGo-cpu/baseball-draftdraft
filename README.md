# baseball-draftdraft

NPBドラフト指名選手で17人を編成するルーレットゲーム（自分用の再現版）。仕様は [docs/SPEC.md](docs/SPEC.md)。

## 画面の構成

```
タイトル（遊ぶ）
└─ メニュー
   ├─ 新しく始める → ルール設定 →（ドラフト開始！）→ ゲーム → 選択終了（完成画面）
   ├─ 続きから → ゲーム
   ├─ 保存したチーム → チームの詳細
   ├─ 遊び方
   ├─ オプション（効果音、データの削除・初期化、アプリの情報）
   ├─ 更新ログ
   └─ クレジット
```

- 画面は URL のハッシュで切り替える（`#/title`、`#/menu`、`#/setup`、`#/game`、`#/saved`、`#/saved/<id>`、`#/howto`、`#/options`、`#/changelog`、`#/credits`）。
- 画面左上の戻るボタンでも、ブラウザやスマホの「戻る」でも、前の画面に戻れる。

## 遊び方

1. タイトル画面の「遊ぶ」→ メニューの「新しく始める」で、ルール（年度範囲・パス上限・育成／入団拒否を含めるか）を決めて「ドラフト開始！」。初期値は 1965〜2025年・パス3・すべて含める。
2. 「ルーレットを回す」で「球団×年度」が1つ決まる（同じ組み合わせは二度出ない）。
3. 指名選手の中から1人を選んで「この選手を指名」→ 枠を選んで確定すると、「第○巡選択希望選手」として発表される。確定した選手は動かせない。いらなければパス。
   - 投手と野手の区別はなく、どの選手もどの枠（スタメン・控え・先発・中継ぎ・抑え）にも入れられる。守備位置も自由。「投手」「内野手」などの登録ポジションは肩書きとして表示する。
4. 配置できる選手が1人もいない（全員がすでにチームにいる）ときは「自動スキップ」で次へ進める（パスは減らない）。
5. 17枠（スタメン9・控え2・先発3・中継ぎ2・抑え1）が埋まったら完成。テキストのコピー、画像の保存、編成の保存ができる。
6. 完成画面の「答え合わせ」で、各選手のキャリアハイ（WAR が最も高い年）の成績と、チームの予想勝利数・総合力（S〜E）が出る。選手をタップすると、ほかの年度に選び直せる（下の「答え合わせ（簡易 WAR）」）。

- 進行中のゲームはブラウザに自動で保存され、リロードしてもメニューの「続きから」で再開できる。
- URL に `?seed=123` を付けると抽選の順番が固定される（動作確認用）。

## 動かし方

ES モジュールと JSON の読み込みを使うので、`file://` では開かず、ローカルサーバーで開く。

```bash
python3 -m http.server 8000
```

ブラウザで http://localhost:8000/ を開く。ビルドや外部ライブラリは不要。

### テスト

```bash
npm test
```

`node --test tests/*.test.mjs` と同じ。Node 22 以上で動く（追加のパッケージは不要）。ルールの単体テストと、実データで300ゲームを自動で遊ばせてルール違反がないかを確かめるテストがある。

### GitHub Pages で公開する

リポジトリの Settings → Pages で、Source を「Deploy from a branch」、Branch を `main` の `/ (root)` にする。公開 URL は https://miyoshigo-cpu.github.io/baseball-draftdraft/ になる。パスはすべて相対パスなので、そのまま動く。

### ホーム画面に追加する（アプリとして使う）

- iPhone：Safari で公開 URL を開き、共有ボタン →「ホーム画面に追加」。Android：Chrome のメニュー →「ホーム画面に追加」または「アプリをインストール」。
- アイコンから開くと、ブラウザのバーがない全画面で起動する。ホーム画面での名前は「ドラルー」（`manifest.webmanifest` の `short_name` と、`index.html` の `apple-mobile-web-app-title`）。
- ホーム画面から開いたアプリは、ブラウザとは別にデータを保存する（iPhone の仕様）。ブラウザで進めたゲームや保存したチームは引き継がれない。
- オフラインでは動かない（毎回、公開ページから読み込む）。そのぶん、更新はアプリを開き直すだけで反映される。

アイコンを作り直すときは、`scripts/build_icons.mjs` の SVG を直してから次を実行する（Playwright を使う）。

```bash
npm run icons
```

## バージョンと更新ログ

- 現在のバージョン：**Beta v1.7**。タイトル画面の下部とメニューに表示していて、タップすると更新ログが開く。
- 更新ログ：[CHANGELOG.md](CHANGELOG.md)（アプリ内の更新ログと同じ内容）
- 前回見たときより新しいバージョンになっていると、タイトル画面とメニューの「更新ログ」に「NEW」が付く（更新ログを開くと消える）。
- 番号の付け方：正式版を出すまではベータ版として「Beta v1.x」と表記し、改良のたびに小数点以下を1つ上げる（Beta v1.3、Beta v1.4…）。すべての改良が終わったら正式版 **v1.0** をリリースする。正式版のあとは、機能の追加・改善・修正やデータの更新で小数点以下を上げ（v1.1…）、大きな作り直しで整数部を上げる（v2.0）。

更新するときの手順：

1. `js/version.js` の `STAGE`（`beta` か `release`）と `VERSION` を変え、`CHANGELOG` の先頭に1件追加する（変更の種類は `new`＝追加、`improve`＝改善、`change`＝変更、`fix`＝修正、`data`＝データ）。
2. `CHANGELOG.md` を作り直す。

   ```bash
   npm run changelog
   ```

3. `npm test` を実行する。`CHANGELOG.md` と `js/version.js` が食い違っているとテストが失敗する。
4. プルリクエストを作って main にマージすると、GitHub Pages に自動で反映される（Claude に作業を頼んだ場合は、確認のあと Claude がここまで行う）。

## 選手データ（`data/players.json`）

- 指名選手の Wikipedia 記事から、プロフィール（投打・守備位置・生年月日・出身地・身長体重・経歴）、NPB 一軍の年度別成績（打撃・投手）、守備位置別の試合数、タイトル・表彰を取り出したもの。
- ゲーム中に、指名選手リストの「詳細」や、マイチームの選手をタップすると見られる（選手の詳細シート）。
- 検証結果（件数、抜き取り確認、NPB として扱わなかった球団表記）は [scripts/players_report.md](scripts/players_report.md)。
- 作り直し：`python3 scripts/build_players.py`（記事を 50 件ずつまとめて取得し、成績の表は Wikipedia 側で 20 人ずつ HTML に変換して読む。初回は 30〜60 分かかる。`--offline` でキャッシュだけから作り直せる）。
- 出典：Wikipedia日本語版の各選手の記事（CC BY-SA 4.0）。

## 答え合わせ（簡易 WAR）

完成画面（と保存したチームの詳細）に出る。計算は `js/war.js`（WAR）と `js/career.js`（年度の選び方・チームの評価）。

- **WAR** は「控えレベルの選手と比べて、その年に何勝ぶん上積みしたか」。公式の NPB の WAR は公開されていないので、成績とリーグ平均から計算する独自の目安。その年・そのリーグの平均と比べるので、投高打低などの時代の差は補正される。
  - 打者：打撃（wOBA＝出塁と長打の価値を重み付けした率が、リーグ平均よりどれだけ上か × 打席）＋守備位置の補正（捕手・遊撃は加点、一塁は減点。一軍の守備位置の試合数で混ぜ、守備成績がなければプロフィールの守備位置）＋控えレベルとの差（打席数に比例）
  - 投手：防御率がリーグ平均よりどれだけ低いか × 投球回（自責点を失点に直す）＋控えレベルとの差（先発は大きく、救援は小さい）。救援で終盤に投げた分（セーブ・ホールドの多さ）は最大 1.5 倍
  - 得点を勝ち数に直す割る数（1勝に必要な得点）は、その年の得点の多さから決める（FanGraphs の式）。リーグ全体の WAR は「勝ち数 − 控えレベルだけのチームの勝ち数（勝率 .294）」で、打者 57%・投手 43% に分ける
  - 守備の上手さ・走塁・球場の違いは、データがないので入れない
- **年度の選び方**：その枠での WAR が最も高い年（打者の枠は打撃、投手の枠は投手の WAR）。中継ぎ・抑えの枠は、80回を超える年を80回分に割り引いて比べる（先発投手を抑えに入れても、抑えとして投げる回数ぶんの価値になる）。シーズン途中で移籍した年は1年にまとめる。選手をタップすると、ほかの年度に選び直せる
- **選手のランク**：WAR 7以上で S（MVP 級）、5以上で A、3以上で B、2以上で C、1以上で D、それ未満は E。中継ぎ・抑えは 3.5・2.5・1.5・1・0.5 で区切る
- **チームの総合力**：17人の WAR の合計（控えは出場が少ないので 1/4）に、控えレベルの選手だけのチームの勝ち数（143試合×.294＝42勝）を足して予想勝利数にする。100勝以上で S（歴代最強クラス）、90勝以上で A（独走で優勝）、82勝以上で B（優勝争い）、74勝以上で C（Aクラス争い）、66勝以上で D（Bクラス）、それ未満は E（最下位争い）。区切りは指名データで自動プレイを繰り返して決めた（よく知られた選手を選んでいくと 73〜101勝、中央値 83勝）
- その枠の成績がない選手（例：投手の枠に一軍の投手成績がない選手）は0
- 選手の詳細シートにも、年度別と通算の WAR を出す

## リーグのデータ（`data/leagues.json`）

- 年度（1965〜2026年）・リーグ（セ・パ）ごとのチーム成績の合計（勝敗、打数・得点・安打・二塁打・三塁打・本塁打・盗塁、投球回・自責点・失点など）。WAR の基準に使う。
- 出典：NPB.jp 日本野球機構「年度別成績」（https://npb.jp/bis/yearly/）と、2005年以降の「チーム打撃成績」「チーム投手成績」。
- 四球・死球・犠飛は 2005年以降しか公式の表にないので、それより前は選手データのその年・そのリーグの「打数あたりの四球・死球・犠飛」から推定している（`estimated: true`。2005年以降で試すと、推定と公式の差はおおむね ±5% 以内）。
- 作り直し：`python3 scripts/build_leagues.py`（212 ページを 1.5 秒間隔で取得。約5分。`--offline` でキャッシュだけから作り直せる）。キャッシュは `scripts/cache/npb/`（コミットしない）。Claude Code のクラウド環境では、ネットワーク設定で `npb.jp` を許可しておく。

## データ（`data/drafts.json`）

- 1965〜2025年度・12球団スロット・731ペア・5,494人（新人 4,868人／育成 626人）
- 1978年の巨人はドラフト不参加のため、ペアを作っていない
- 検証結果（年度×球団の人数表、同姓同名、再指名された選手など）は [scripts/report.md](scripts/report.md) にまとめている

### 作り直す方法

```bash
pip install -r scripts/requirements.txt
python3 scripts/build_drafts.py            # キャッシュがない年度だけ取得して生成
python3 scripts/build_drafts.py --offline  # 取得せず、キャッシュだけで生成
python3 scripts/build_drafts.py --refresh  # 全年度を取り直して生成
```

- 記事 HTML は `scripts/cache/{年}.html` にキャッシュする（コミットしない）。
- MediaWiki API へのリクエストは1秒間隔。HTTP 429 などが返ったときは `Retry-After` に従って待ち、自動で再試行する。
- Claude Code のクラウド環境で動かす場合は、環境のネットワーク設定で `ja.wikipedia.org` を許可しておく。
- 終了コード：0＝成功、1＝生成はしたがチェック（球団数・人数0・抜き取り確認など）に NG がある、2＝対応表にない球団名などで停止。

### 手で直すとき

| ファイル | 用途 |
|---|---|
| `scripts/franchise_map.json` | 当時の球団名 → 球団スロット id の対応表。ここにない球団名が出たら生成を止める |
| `scripts/overrides.json` | 個別の補正（二刀流フラグ、同姓同名の区別、表の崩れの補正）。`match` は1件の指名にだけ一致させる |

`overrides.json` の書き方：

```json
{"match": {"year": 2012, "franchiseId": "fighters", "name": "大谷翔平"}, "set": {"twoWay": true}, "reason": "二刀流"}
```

- `match`：`year` / `franchiseId` / `name`（必要なら `roundLabel`）
- `set`：`roundLabel` `name` `playerKey` `pos` `from` `draftType` `signed` `twoWay` `note` を変更できる
- `remove: true`：その指名を削除する
- 0件または2件以上に一致した上書きはエラーにする（記事が変わって上書きが古くなったことに気づけるように）

### データの決めごと

- `roundLabel`：記事の表記に、区分に応じた接頭辞を付ける
  - 1966年：`1次` / `2次`（例：`1次1位`）
  - 2005〜2007年：`高校` / `大社`（例：`高校1巡目`、`大社希望入団枠`）
  - 育成指名：`育成`（例：`育成1位`）
- `signed: false`：結果・備考の列に「拒否」「交渉権放棄」「指名取消」「指名無効」のいずれかがある指名
- `note`：結果・備考の列の原文（「入団」だけの場合は空）
- 「（選択権なし）」「（指名権剥奪）」の行は指名ではないので除く
- `name`：記事の表記（指名当時の名前）をそのまま使う。例：1991年 オリックス 4位は「鈴木一朗」（のちの登録名「イチロー」ではない）
- `playerKey`：氏名の空白を除いたもの。記事内のリンク先で同一人物かどうかを確かめている
  - リンク先が別の記事になっている同姓同名の別人（16組）は、`overrides.json` で `坂本勇人(捕手)` のように分ける
  - 同じ選手記事にリンクしているのに表記が違うもの（尾形正己／尾形正巳、平田恒雄／平田恒夫）は、playerKey をそろえる
- 脚注番号と、他言語版へのリンク表記（「（英語版）」など）は取り除く
